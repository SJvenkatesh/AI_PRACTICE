# Example A — Orchestration flow (Wise Albert)

**Orchestration** is the layer *above* individual agents. Multi-agent systems
(Topic 6) showed several agents cooperating. Orchestration adds the control
logic that decides — per request — *which* agents to run, in what order, how to
merge their outputs, and whether a human must approve before the result ships.

```
┌─────────────────────────────────────────────────────────────┐
│ TRIGGER                                                       │
│ "Why did activation drop? Any QBR commitment at risk?"        │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 1: INTENT CLASSIFIER                                     │
│ → intent: ["kpi_anomaly", "promise_risk"]                     │
│ → persona: cs_lead                                            │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ STEP 2: AGENT PLANNER                                         │
│ → run: probing_agent, adoption_agent (parallel)               │
│ → skip: personal_intel (not needed)                           │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
         ┌──────────────────┼──────────────────┐
         ▼                  ▼                  ▼
   ┌───────────┐     ┌───────────┐     ┌───────────┐
   │ Probing   │     │ Adoption  │     │Prediction │  (skipped)
   └─────┬─────┘     └─────┬─────┘     └───────────┘
         └──────────────────┼──────────────────┘
                            ▼

                            ▼

```

## How it works internally — orchestration as a state machine

```
INIT → CLASSIFIED → RUNNING → MERGED → NARRATED → REVIEW → DONE
                                            ↑         │
                                            └─ reject ┘
```

LangGraph compiles this into a directed graph:

- **Nodes** = functions (classify, agent, merge, narrate, hitl)
- **Edges** = fixed transitions
- **Conditional edges** = routing (if approved → END else → revise)
- **State** = a TypedDict passed and updated at each node
- **Checkpointer** = persists state so a HITL pause can resume later

### What lives in state

```python
state = {
    # Input
    "question": str,
    "persona": str,
    "trigger_type": "chat|schedule|alert",
    # Routing decisions
    "intents": list,
    "agents_to_run": list,
    # Agent artifacts (structured JSON only — not prose)
    "probing_result": dict,
    "adoption_result": dict,
    # Merged
    "evidence_package": dict,
    # Output
    "draft_answer": str,
    "approved": bool,
    "citations": list,
    # Control
    "step_count": int,
    "errors": list,
}
```

### Intent classification options

| Method | Pros | Cons |
|--------|------|------|
| LLM classifier | Flexible, few-shot | Latency + cost |
| Rules / regex | Fast, cheap | Brittle |
| Small ML model | Fast at scale | Needs training data |
| Hybrid | Best in production | More code |

Practical path: start with an LLM classifier, then add rules for known triggers
(e.g. a scheduled `weekly_digest` doesn't need an LLM to classify).

### Evidence bus responsibilities

The evidence bus turns messy agent outputs into a clean package for the
narrative LLM:

1. Collect agent JSON outputs
2. Dedupe the same metric reported by two agents
3. Resolve conflicts (Probing says red, Prediction says amber → flag it)
4. Score confidence per claim
5. Attach lineage (`source_id`, `agent_id`, timestamp)
6. Package for the narrative LLM

```
Agent outputs (messy) → Evidence bus (clean) → Narrative LLM (readable)
```
