# Example F — Workflow types

Orchestration isn't one shape — it's a toolkit of control-flow patterns you
combine. Most real pipelines use several at once (e.g. scheduled trigger →
branching → parallel fan-out → fan-in → HITL loop).

| Pattern | When | Example |
|---------|------|---------|
| **Linear** | Fixed steps | ingest → chunk → embed |
| **Branching** | Intent-dependent | QBR path vs simple KPI lookup |
| **Parallel fan-out** | Independent agents | Probing + Adoption together |
| **Fan-in** | Merge results | Evidence bus |
| **Loop / retry** | Quality gate | HITL reject → revise narrative |
| **Scheduled** | Cron trigger | Monday 7am weekly digest |
| **Event-driven** | Alert threshold | KPI breach → Risk Flash Alert |

Where each shows up in this topic's files:

| Pattern | Seen in |
|---------|---------|
| Branching | `2.intent_router.py` (intent → agent set), `3.langgraph_orchestration.py` |
| Parallel fan-out | `4.parallel_dispatch.py`, `6.Multi_Agent_Systems/3.langgraph_supervisor.py` |
| Fan-in | evidence bus node in `3.langgraph_orchestration.py` |
| Loop / retry | conditional `revise` edge in `3.langgraph_orchestration.py` |
| HITL gate | `5.hitl_interrupt.py` |
| Linear | the RAG pipeline in `3.RAG/6.full_pipeline.py` |

**Scheduled** and **event-driven** are *triggers* rather than in-graph shapes —
a cron job or an alert threshold fires the same orchestration graph the chat
trigger would. The graph doesn't care what woke it up; only the `trigger_type`
in state differs.
