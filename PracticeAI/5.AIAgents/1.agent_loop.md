# Example A — Agent loop (conceptual)

An **agent** is an LLM that runs in a loop: it THINKS about what it needs, ACTs
by calling a tool, OBSERVES the result, and repeats until it has enough to
answer. Unlike a fixed RAG pipeline (retrieve → generate, always the same
steps), the agent *chooses* which tool to call and in what order.

```
┌─────────────────────────────────────────┐
│  USER: "Why did activation drop?"        │
└──────────────────┬──────────────────────┘
                   ▼
         ┌─────────────────┐
    ┌───►│  LLM: THINK      │◄───┐
    │    │  "I need KPI     │    │
    │    │   D-110 first"   │    │
    │    └────────┬─────────┘    │
    │             ▼              │
    │    ┌─────────────────┐    │
    │    │  ACT: call tool  │    │
    │    │  get_kpi(D-110)  │    │
    │    └────────┬─────────┘    │
    │             ▼              │
    │    ┌─────────────────┐    │
    │    │  OBSERVE result  │    │
    │    │  12k vs 24k      │────┘
    │    └────────┬─────────┘
    │             ▼
    │    ┌─────────────────┐
    │    │  LLM: THINK      │
    │    │  "Need ops notes"│
    │    └────────┬─────────┘
    │             ▼
    │    ┌─────────────────┐
    │    │  ACT: rag_search │
    │    └────────┬─────────┘
    │             ▼
    │    ┌────────────────────┐
    └───►│  DONE: write answer │
         └────────────────────┘
```

## The three moves

| Move | What happens | In code |
|------|--------------|---------|
| THINK | LLM decides the next step | the model's reasoning |
| ACT | LLM emits a tool call with arguments | `tool_calls` on the response |
| OBSERVE | your code runs the tool, feeds the result back | append a tool-result message |

The loop ends when the LLM stops asking for tools and just answers. A `max_steps`
cap prevents runaway loops.

Gemini tool-calling.
